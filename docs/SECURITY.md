# WAAFA security checklist (launch, 11 Oct 2026)

PRD NFR-SEC and the OWASP Top 10 (2021), mapped to what the code does. Re-check before every major release.

| OWASP risk | Controls in WAAFA | Where |
| --- | --- | --- |
| A01 Broken access control | Staff roles per PRD §4 on every admin endpoint (`@Roles`, `StaffGuard`); leads and content filtered by role (outside a role → 404); Super Admin only for users and API connections; admin at a non-guessable path (`/secure-admin-control`), `/admin` is a 404; the API is not public (only nginx is) | `apps/api/src/admin`, `apps/api/src/auth`, `deploy/compose.yml` |
| A02 Cryptographic failures | HTTPS only (Let's Encrypt, HSTS); argon2id passwords; refresh tokens stored as hashes; provider API secrets sealed with AES-256-GCM (`PROVIDER_SECRET_KEY`); secrets only in `deploy/.env` (mode 600, generated by `init-env.sh`) | `apps/api/src/providers/secretBox.ts`, `deploy/` |
| A03 Injection | Prisma parameterised queries (raw SQL only with tagged templates); every input parsed by the shared zod schemas with unknown fields rejected; admin rich text sanitised server-side with an allow-list; JSON-LD escapes `<` | `packages/shared`, `components/content/RichText.tsx`, `components/seo/JsonLd.tsx` |
| A04 Insecure design | Prices and totals recalculated on the server (never trusted from the browser); idempotency keys on every form; Live booking locked until Phase E; fares labelled indicative | `packages/shared/src/helpers/orderPricing.ts`, `apps/api/src/public` |
| A05 Security misconfiguration | CSP, X-Frame-Options, nosniff, Referrer-Policy, Permissions-Policy, COOP on every page; helmet on the API; OpenAPI only outside production; `x-powered-by` off; nginx drops unknown hosts (444) and hides its version | `apps/web/src/lib/security/securityHeaders.ts`, `deploy/nginx` |
| A06 Vulnerable components | Dependabot, CodeQL, `pnpm audit` (see below); images rebuilt on every deploy from pinned bases | `.github/` |
| A07 Identification and authentication failures | 15-minute access tokens, rotating 7-day refresh tokens with reuse detection, httpOnly SameSite cookies on the web; login rate limit (5 per 15 min per address) and a 15-minute lockout after five failed passwords or codes; 12+ character passwords; two-step sign-in (TOTP, RFC 6238) required for Super Admin and Admin, with one-time recovery codes (hashes only), replay protection, 30-day trusted devices, a sign-in history and a new-device email (issue 234) | `apps/api/src/auth` |
| A08 Software and data integrity failures | Signed (HMAC) revalidation calls with a 5-minute age limit; server-to-server intake key; migrations run in the deploy; squash-merged PRs with green CI only | `apps/web/src/app/api/revalidate`, `apps/api/src/revalidate` |
| A09 Logging and monitoring failures | Every admin write in the audit log with before and after values; pino request logs with request IDs; email delivery log; daily database backups with a tested restore | Admin › Audit log, `deploy/backup.sh` |
| A10 Server-side request forgery | The provider health check only reaches public https hosts (no localhost, private ranges, IP v6 literals or single-label names); no other user-supplied URL is fetched | `apps/api/src/providers/catalogAdapters.ts` |

Forms: Cloudflare Turnstile (when the keys are set), per-address rate limits in the web, the API (in Redis, shared by every process and kept across restarts, plus 10 lead requests an hour per phone number; issue 234) and nginx (30 POSTs a minute), body size caps (web 16 KB per form, API 1 MB, nginx 2 MB).

Customer files (issue 232): visa documents, payment slips, printing and trading attachments and feedback photos upload
to `/api/uploads` (nginx 6 MB, web and API 5 MB, JPG, PNG or PDF decided by the first bytes, 20 a minute per visitor,
40 MB of unclaimed files per visitor and 2 GB in total, uploads pause below 2 GB free disk). They live on the private
`privatedata` volume, which nginx never serves. Staff open a file only through a 10-minute signed link from the admin;
issuing the link and each download are written to the audit log, and staff see only files of records their role can
open. Unclaimed uploads are deleted after 6 hours and visa documents 90 days after the application closes. Payment
slips, attachments and feedback photos stay with their record. Nightly backups keep the private files for 14 days in
owner-only archives; copy them off the server only to an encrypted place (the off-site copy in #239 encrypts them).

## Dependency audit (11 Oct 2026, `pnpm audit --prod`)

| Package | Severity | Path | Assessment |
| --- | --- | --- | --- |
| mysql2 | high, moderate | `prisma` CLI → `mysql2` | Not used: WAAFA runs on PostgreSQL and never opens a MySQL connection. Clears when Prisma updates the dependency |
| deepmerge-ts | high | `prisma` → `@prisma/config` | Merges our own Prisma config only, never visitor data. Clears with a Prisma update |
| braces | high | `eslint-config-next` → … → `braces` | Lint tooling only; not in the runtime images; no fix published yet |

No exploitable runtime finding. Dependabot opens the updates as they appear.

## After go-live

- Turn on Turnstile (site key and secret in `deploy/.env`) once the domain is final.
- Add an uptime monitor (e.g. UptimeRobot, free) on `https://<domain>/` and keep the backups copied off the server weekly.
- Change the first Super Admin password after the first sign-in and remove `SEED_ADMIN_*` from `deploy/.env`.
